Highest ROI by a mile.</p><p><strong>Layer 2</strong> &#8212; Knowledge (User(.)md + Memory)</p><p>What the agent KNOWS about you. Your portfolio, your theses, your preferred sign-offs, your past mistakes. This compounds every session &#8212; the more you correct it, the better it gets. Time investment: high over time, but the first draft takes 30 minutes.</p><p><strong>Layer 3</strong> &#8212; Tools (Config + Skills)</p><p>What the agent CAN DO. API keys, cron jobs, browser access, Dune queries. This is where most people start and stop. Table stakes. Makes the agent capable but not differentiated.</p><p>Knowing what to focus on can make or break your Hermes agent.</p><div><hr></div><h2><strong>What to focus on when setting Hermes up</strong></h2><h2><strong>1. Model Configuration</strong></h2><p>I spent the first week finding the right models for Hermes. I tried plugging it into Claude subscription (until they banned agent harnesses), tried many models on OpenRouter (free, open models, frontier models), tried Opencode Go, tried DeepSeek &#8212; all with the goal to optimize the cost while maintaining top inference quality for Hermes.</p><p>What I found</p><ul><li><p>Start with Opencode Go, it&#8217;s only $5 for the first month and offers &gt;$50 of inference value from top open models like Kimi k2.6 &amp; GLM5.1 both great for long-running tasks or MiniMax 2.5 - 2.7 which are great for basic tasks (very fast). Set MiniMax 2.7 as basic usage and Kimi k2.6 or GLM5.1 as delegate_task for complex tasks</p></li><li><p>After Opencode Go, continue with DeepSeek (or just start with DeepSeek if you want) because they have sharp 75% discount on DeepSeek v4 Pro in May. DeeepSeek v4 Flash is fast &amp; efficient at basic task and Pro is great for complex tasks</p></li></ul><p>If you don&#8217;t wanna waste money at all, you can explore free models on OpenRouter. The only downside is that many people are usually using the free model which can be VERY SLOW at times OR you may get rate-limited/not be able to access it, they&#8217;re not reliable so it&#8217;s better to spend $5 for OpenCode Go.</p><p>The only down side to OpenCode go is the speed. Takes a bit of time for your prompt to go through (apparently the prompt goes to OpenCode and to Model Provider so it&#8217;s 2+ hops which take a little bit more time than direct model access).</p><p>There are 2 files you need to be mindful of (i) config.yaml (ii) .env </p><ul><li><p><strong>config.yaml</strong> is where you adjust the model provider and input your model API key</p></li><li><p><strong>.env</strong> is your environment variable, you put in APIs from tools &amp; models here</p></li></ul><p>These 2 are important because it&#8217;s much faster for you to adjust the model provider and the model here than prompting Hermes to do so (saves you a lot of time &amp; tokens if you do it yourself)   </p><p>Oh.. forgot to mention, if you&#8217;re very concerned about privacy, use @AskVenice subscription. They have zero data retention policy + TEE so your prompts/data are private. They also have tokenized inference DIEM, 1 DIEM gets you $1 credit per day (if you want to invest + get credits at the same time)</p><p>I&#8217;m quite excited about @dphnAI because soon (in a month according to the team), POD will start to give platform credits for Dolphin inference network (similar to DIEM). It&#8217;s like 2 birds with 1 stone (i.e. investing in a growing private inference network while getting free inference credits)</p><div><hr></div><h2><strong>2. Soul and User Configuration</strong></h2><p>If model config = the plumbing, soul &amp; user config = the persona</p><p>In Hermes&#8217; words:</p><p>&#8220;How I write, Jeff&#8217;s theses, the portfolio, the voice constraints (&#8221;no sounding smart like LLM&#8221;, &#8220;casual narrator voice&#8221;, &#8220;contrarian first&#8221;) &#8212; that&#8217;s the Soul layer. Without it, I&#8217;m a generic chatbot with tools. With it, I&#8217;m Jeff&#8217;s second brain that writes in his voice and knows what he&#8217;d care about before he finishes typing&#8221;</p><p>Soul(.)md = who the agent is &#8594; determines everything downstream</p><p>User(.)md = who you (the user) are &#8594; prevents re-explaining</p><p>Most people skipped this step. They installed Hermes, plugged in model API, connected some tools, and started using it. And then they wondered why Hermes is not impressive.</p><p>Spend an hour or two talking to Hermes about </p><ul><li><p>The goal you&#8217;re trying to achieve with him</p></li><li><p>Who he is &#8212; an analyst, a writer, a coder, a general assistant</p></li><li><p>How he speaks &#8212; professional, casual (I fed him my articles so he talks like me)</p></li><li><p>Operating constraints &#8212; I have over a decade in PE/VC/IB so I like for Hermes to frame everything through the lens of unit economics </p></li><li><p>Investment theses, portfolio positions, risk tolerance &#8212; these get stored in User(.)md so Hermes knows what I&#8217;ll care about or what I&#8217;ll ignore</p></li></ul><p>Soul and User configuration are never truly finished. I iterated on Soul 5-6 times already and User config gets updated every single day based on my positions + theses which may get invalidated or adjusted based on the market.</p><p>So yeah... take your time and talk to your Hermes. You&#8217;ll get to reflect, learn more about yourself, and be a better person at the end of it (plus you get a smart dynamic second brain that grows with you).</p><div><hr></div><h2><strong>3. Skills</strong></h2><p>The coolest part about Hermes is that it automatically create skills for you. A skill is like a recipe that the agent can load and execute workflows without re-explaining anything. You do something once &#8594; if the agent thinks you&#8217;ll likely do it again &#8594; it creates a skill so that the 2nd time is a lot easier &amp; faster</p><p>Skill can be a double-edged sword at times. If you&#8217;re experimenting with tools a lot early on, Hermes could be creating lots of skills, he could be remembering the tools API that don&#8217;t work well and could be creating cron jobs with it. If there are many skills and many scheduled cron jobs around, things can get messy &amp; chaotic.</p><p>What I find very helpful is</p><ul><li><p>Remembering the tools that&#8217;re great. If the agent choose a non-efficient way/tool to tackle a task, you can interrupt it and point it towards the right tool and tell him to remember for the next time</p></li><li><p>Explicitly tells Hermes to update cron jobs and update other workflows that rely on a tool once you change or adjust it</p></li><li><p>Constantly check for tools that don&#8217;t work, redundant texts, and unreliable workflows. Tell Hermes to work with sub-agent (via delegate task) to do a health check multiple times to ensure tools &amp; workflows are in good shapes</p></li></ul><p>You gotta remember that workflows can get bloated very quickly if you have too many tools/skills, especially ones that don&#8217;t work. Because every time you prompt it, it&#8217;ll waste tokens going through tools that don&#8217;t work.</p><div><hr></div><h2><strong>4.
